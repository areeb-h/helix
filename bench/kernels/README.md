# Kernel benchmarks — Helix vs C / Rust / Go / CPython / NumPy

A permanent, re-runnable, self-verifying comparison against **compiled** languages.
(The sibling [`bench/crosslang/`](../crosslang) compares against the Python
scientific stack; [`bench/stress/`](../stress) covers bio-shaped workloads.)

```sh
./run.sh                 # verify anchors, then time everything (best of 3)
./run.sh --verify        # anchors only — exits 1 if any language disagrees
./run.sh --scale 0.02    # 2% sizes for a quick check
./run.sh k1_dot k5_montecarlo     # just these
HELIX=/path/to/helix ./run.sh     # force a binary
```

## The rules this suite runs by

**1. The anchor gate comes before any timing.** Every language implementing a
kernel must print the byte-identical anchor, or `run.sh` exits 1 and reports no
numbers. A benchmark whose languages compute different things measures nothing.
This has caught real bugs — including a sieve "reference" anchor that was
silently the `x/ln x` *estimate* rather than π(10⁷).

**2. The gate must be able to fail.** An earlier hand-written checker in this
directory only *echoed* each language's output for a human to eyeball; an
auditor proved it green after sabotaging one language's arithmetic. It was
deleted. `run.sh` compares and exits non-zero.

**3. The anchor must require the work.** An anchor a cheater could compute
without doing the computation tests nothing. The first draft of `k7_wordcount`
used a generator whose word counts were structurally flat, making the anchor
identically `ceil(N/10000)` — an auditor wrote a three-line `cheat.c` that
counted nothing and passed at every N. The generator was replaced with the
xorshift64 stream already proven in `k5`.

**4. Report what a win cost.** Helix auto-parallelizes some array kernels; the
C/Rust/Go references are single-threaded standard-library loops. `run.sh` prints
`%CPU` beside wall time, so a wall-clock win bought with 3× the cores cannot
masquerade as a codegen win.

**5. Equalize the platform, or disclose it.** Helix links mimalloc, which
`madvise`s transparent huge pages; glibc `malloc` does not. On allocation-heavy
kernels that is worth ~3.5× and says nothing about the language. `run.sh`
exports `GLIBC_TUNABLES=glibc.malloc.hugetlb=1` so the C/Rust references get the
same page treatment. **Go has no equivalent knob — its number is not
page-size-equalized, and we say so rather than quietly dropping it.**

**6. Name what the kernel actually measures.** "Dot product" that spends 94% of
its time building arrays is an allocator benchmark wearing a math label. Each
kernel's header says what it really ranks.

## The kernels

| # | Kernel | Default N | What it actually measures |
|---|--------|-----------|---------------------------|
| k1 | `dot` — i64 dot product | 50M | Allocator + page-fault behavior and array construction (**the dot is ~6% of the runtime**) |
| k2 | `mandelbrot` — escape-time | 1200² | Scalar FP codegen and branch prediction. Single-threaded everywhere |
| k3 | `basel` — Σ1/k² in order | 100M | Serial FP-add latency. ~64–99% of every compiled entry is the shared hardware latency floor, so it *under*-discriminates codegen |
| k4 | `allpairs` — Manhattan | 15k pts | Codegen + auto-vectorization on an L2-resident array. Single-threaded everywhere (Helix's parallel path declines triangular ranges) |
| k5 | `montecarlo` — xorshift64 π | 100M | Scalar integer/FP codegen on a bit-exact shared RNG stream |
| k6 | `sieve` — π(10⁷) | 10M | **Delegation**: does the language ship the right primitive? (Helix calls a native builtin; `k6_sieve_trial.helix` shows the honest pure-Helix cost) |
| k7 | `wordcount` — 5M words | 5M | String building + hashing. Helix and NumPy materialize the corpus (O(N) resident); the others stream |
| k8 | `matmul` — dense f64 | 1024³ | **Delegation**: `k8_matmul.helix` calls a GEMM (faer) vs NumPy's OpenBLAS; `k8_matmul_naive.helix` is the honest triple-loop peer for C/Rust/Go/CPython |

## Adding a kernel

1. Write the Helix version first, then port it *literally* to each language —
   same algorithm, same operation order, same data.
2. Pick an anchor that **requires the whole computation** and is
   formatting-stable (prefer an integer; for floats, print raw bits or a fixed
   `%.17f`, never `%g`-style significant digits unless you have verified the
   string matches).
3. `./run.sh --scale 0.001 <kernel>` until every language agrees, then at full N.
4. Write the header: what it measures, what it does *not*, and every flag with
   a reason. If you cannot verify a claim, delete it rather than soften it.

Helix specifics: it has no `argv` — kernels read N from stdin via `read_int()`,
so **always redirect stdin** (a bare `helix run` blocks forever waiting for a
line). Integers are i64 with an arithmetic `>>`; mask after shifting to
reproduce C's unsigned shift (see `k5_montecarlo.helix`). Its `%` is *floored*,
not truncated — never take `%` of a possibly-negative value and expect C's
answer.
