# Architecture Decision Records

Each ADR captures one foundational Helix design decision: the context, the
decision, the rationale, and the rejected alternatives (with reasons). These are the
decisions that are expensive or impossible to reverse once code depends on them, so
they are made deliberately and in the open.

| [0039](0039-string-predicates-in-queries.md) | Should a String predicate be usable inside a DataFrame query? | **Accepted & implemented** — `starts_with`, `ends_with`, `contains` and the `re_` family work on a column expression, with `contains` LITERAL and `re_match` a PATTERN exactly as on scalars (ADR 0036); `missing` propagates, which only `with` can show since `where` drops the row either way; ships in v0.7.0 |
| [0040](0040-workspaces.md) | A repo of several packages: can one directory be both a package and not the module root? | **Accepted & implemented** — `helix.toml` carried two meanings at once ("this is a distributable package" and "imports anchor here") and `project_context` stops at the NEAREST one, so a repo with a manifest per package made each package its own root and `import ui.parse` inside `ui/` looked for `ui/ui/parse.helix`. A `[workspace]` table names members; the root anchors and the members stay packages. An unlisted package is untouched, a missing member is refused by name, and a member's own `[dependencies]` is refused rather than silently unresolved |
| [0041](0041-durable-storage-substrate.md) | Can a correct storage engine be written IN Helix? | **Accepted & implemented** — it could not be: the filesystem surface had no `rename`, `fsync` or `rmdir`, so write-temp-then-rename was inexpressible and "written" meant "reached the page cache". Nine verbs added as ONE set, because a partial durability story is worse than none — a program that calls `fsync` and skips `sync_dir` believes it committed and did not. Atomicity (`rename`, `create_new`), durability (`fsync`, `sync_dir`), random access (`file_size`, `read_at`, `write_at`, `truncate`) and lifecycle (`remove_dir`, empty-only and never recursive). `sync_dir` answers `false` where the platform cannot flush a directory rather than claiming a guarantee it cannot keep. All capability-gated. The ceiling is that a `Str` is UTF-8, so this supports a text-structured store and arbitrary binary needs a `Bytes` type |
| [0042](0042-bytes.md) | Can a Helix value hold bytes that are not text? | **Accepted & implemented** — it could not: a `Str` is UTF-8 by definition, so ADR 0041's `read_at` had to refuse a slice splitting a character, and a packed integer, bitmap, compressed block or digest had no representation. `Value::Bytes`, ordered LEXICOGRAPHICALLY by byte (the order a key index needs, and the order `to_hex()` preserves). Widening `Str` was never the alternative — every string operation would then have to answer "what if this is not text". `to_string()` can FAIL and refuses rather than substituting U+FFFD; printing is hex, in full, never truncated. Out of the first cut and refused BY NAME rather than silently: dict keys (use `to_hex()`), JSON (use `to_base64()`), DataFrame columns |
| [0043](0043-row-windows-and-runtime-schemas.md) | Can a frame be windowed by row, and can its schema come from the data? | **Accepted & implemented** — neither: a DataFrame had `head(n)` and nothing else, so a sorted frame could not be cut into chunks; and `dataframe()` takes a RECORD whose fields are syntax, so a column could not be named at run time. Both forced a caller-supplied closure — the same shape, twice. `tail(n)` and `slice(offset, len)` through the ADR 0012 seam, CLAMPED at both ends like `read_at` (a window off the end is how a final partial chunk reads; refusing would force materializing the row count on a lazy frame), with a NEGATIVE offset refused because that question is `tail`'s. `dataframe(dict)` for runtime schemas, columns in SORTED name order — a Dict has no insertion order, so inventing one would be a claim nothing supports |
| [0044](0044-postgresql.md) | Can Helix talk to PostgreSQL without taking on a driver stack? | **Accepted & implemented** — yes. The wire protocol has been frozen since 2003 (18 added 3.2, 19 carries it, backward-compatibly, and `libpq` still requests 3.0), and SCRAM-SHA-256 needs only `sha2`/`hmac`/`base64`/`OsRng` — all already core — so a hand-rolled client adds **zero dependencies**, where `libpq` would have ended the no-system-dependency property and a driver crate would have brought an async runtime into a synchronous language. Reuses every ADR 0038 decision; the one that could not carry over is read-only, since a socket has no such mode, so the SERVER enforces it — set in the STARTUP packet, before a statement could be sent, at zero round trips — and the capability label is `net` rather than `fs-read`. **TLS is on by default and the server cannot turn it off**: two modes rather than `libpq`'s six, because `prefer` (its default, and Go's) continues in plaintext whenever the server says so, and `require` encrypts without checking who answered. A connection is a value whose socket shuts when the last handle goes — no `close` to forget. Verified against PostgreSQL 19 Beta 3 |
| [0045](0045-receiver-directed-methods.md) | Which `where` does `q.where(c)` mean? | **Accepted & implemented** — whichever one the RECEIVER has. UFCS was gated at parse time on "no type owns this name", a global test made where the receiver does not exist, so `fn where`/`select`/`first`/`count`/`all`/`join`/`sort`/`take`/`get`/`sum` — the whole vocabulary of a fluent library — were invisible in method position, and a query builder could not be written in the language. A failed dispatch now retries as `name(recv, …)` against a declared `fn`; the two families compiled by TYPE (column verbs, comprehension loops) emit BOTH readings behind a new `Op::ReceiverIs`, whose predicate the tree-walker calls rather than restates. Found and fixed a pre-existing VM-vs-walker divergence in `Op::DfColumnVerb`'s error |
| [0046](0046-record-destructuring.md) | What does `let {where, limit} = spec` answer for a field the record lacks? | **Accepted & implemented** — `missing`, the answer `get` gives: a spec record's fields are optional by nature, and this form exists to replace six `get` dispatches (38% of a render, a field report measured) with one line of field reads. Desugared in the parser to a temp binding and one absence-tolerant field read per name — a new AST node, so no pass can mistake it for a plain read; the checker still refuses a name a KNOWN record cannot have, in `.a`'s words. Also inside `do { }` and as a top-level statement (`mut`/`export` per field). No renames, no nesting |
| [0047](0047-database-writes.md) | How does a Helix program WRITE to a database, when ADR 0044 holds every session read-only from its first byte? | **Accepted & implemented** — in a different session, spending a different grant. `postgres_execute(url, sql, params?)` and `postgres_open(url, "write").execute(...)` open the one kind of session whose startup packet omits the read-only default, and answer `{affected, rows}` — the count from the completion tag and a frame of `RETURNING` rows in the same round trip. The authority is `db-write` (`HELIX_ALLOW_DB=write`, `[capabilities] db = "write"`), required ALONGSIDE `net`, so granting the network still keeps a program read-only. One statement is one transaction; spanning ones are the open item. Verified against a fake wire server — and the gate now builds `--features postgres`, so those tests run |
