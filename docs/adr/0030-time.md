# ADR 0030 — Can a reproducible language tell the time?

- **Status:** **Proposed 2026-08-16** — recommendation argued below; awaiting owner
  acceptance. Nothing implemented.
- **Date:** 2026-08-16
- **Deciders:** Areeb + Claude
- **Related:** [ADR 0020 — Reproducibility](0020-dict-ordering-and-reproducibility.md)
  (seeded RNG is the precedent this must answer to),
  [ADR 0021 — Capabilities](0021-capabilities.md) (effects are declared, not ambient),
  [ADR 0003 — Collection API](0003-collection-api.md) (one verb per concept).

## Context

Every field session benchmarking Helix code has had to difference whole-process wall
clocks from the *outside* — there is no way to time anything from inside the language.
The nn report calls it "the only item that *blocks* rather than limits." The need is
real and specific: **measure a section of a program**, usually to compare two spellings
or check a complexity class.

The collision is also real. Helix's flagship claim is one program, one answer, three
engines byte-identical — and the house already faced this once with randomness, where
the answer was **seeding**: `random()` is reproducible by construction (ADR 0020). A
clock cannot be seeded. A program that prints a raw timestamp prints a different byte
stream every run, on every engine, and the differential oracle — the correctness model
— goes blind exactly where it is pointed.

## Options

**(a) `now()` returning wall-clock seconds.** The obvious spelling and the wrong one:
wall clocks jump (NTP, suspend), differences can be negative, and it invites timestamps
into data where reproducibility matters most.

**(b) `now()` returning a monotonic instant, as a plain pure-looking builtin.** Honest
for durations, but it would be the first builtin whose result is nondeterministic while
*looking* pure — `describe` says `pure: true` for everything shaped like it, and the
oracle has no way to know which outputs are clock-derived.

**(c) The recommendation: `now()` as a declared EFFECT, monotonic, for durations.**
- `now()` → `Float` seconds from an arbitrary monotonic origin (differences are
  meaningful; absolute values deliberately are not — the origin varies per process, so
  nobody is tempted to print or store one as data).
- Its effect label is **`clock`** — a new `Effect` alongside `fs-read`/`net`/`env`,
  visible in `helix describe`, gateable by the capability system like any effect. The
  language stays honest: a program that reads the clock *says so* in its manifest of
  effects, and a pure program provably contains no clock.
- **The oracle contract:** raw clock values are outside the byte-identical guarantee —
  necessarily, definitionally. The documented benchmark idiom therefore prints
  *judgments*, not times: ratios, pass/fail against a threshold, complexity classes.
  A doc example that prints `now()` cannot be pinned and `helix test` should say so
  rather than flake (reject clock-printing `>>>` examples with a clear error, the same
  honesty the assert-nothing rule shows).

**(d) Keep time outside the language: a `helix bench` subcommand / `--time` flag.**
Cleanest for reproducibility (the language stays clock-free) and worth having
*eventually* for whole-program timing — but it cannot time a section, which is the
actual field need, so alone it does not close the gap.

## Recommendation

**(c), with (d) as a later complement.** The precedent is exact: randomness got in by
being made *declarable and reproducible* (seeding); time cannot be reproducible, so it
gets in by being made *declarable and delimited* — monotonic-only (no timestamps-as-data
temptation), effect-labeled (visible in `describe`, gateable), and documented with the
judgment-not-raw-times idiom so benchmark programs keep oracle coverage for everything
except the one number that cannot have it.

## Consequences (if accepted)

- `now` lands in the registry with `effect: clock`, arity 0, returns `Float` — the
  signatures catalog stays honest automatically.
- The three engines share one implementation site (a builtin), so parity is structural;
  the oracle's blindness is confined to programs that *print* clock values, which the
  effect label makes identifiable.
- Field sessions can finally measure in-process: `t0 = now(); …; print(now() - t0 < 0.1)`
  — a pinnable judgment.
- The `helix test` doc-example rejection for clock-printing examples ships in the same
  change, so the executable-docs guarantee never silently degrades.
